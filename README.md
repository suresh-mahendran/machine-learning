# Student Performance Classification

## a. Problem statement

Use demographic, family, and school-related information to classify whether a
Portuguese-course student fails (`G3 < 10`) or passes (`G3 >= 10`) the course.
The fail class is encoded as `failed = 1` and is treated as the positive class.
The final grade (`G3`) and period grades (`G1`, `G2`) are excluded from model
inputs to prevent target leakage and to evaluate predictions without prior grades.

This is a course exercise, not a validated tool for making decisions about
individual students.

## b. Dataset description

- **Dataset:** Student Performance, Portuguese course (`student-por.csv`)
- **Source:** [UCI Machine Learning Repository - Student Performance](https://archive.ics.uci.edu/dataset/320/student%2Bperformance)
- **Rows:** 649
- **Original columns:** 33
- **Input features:** 30 after excluding `G1`, `G2`, and `G3`
- **Target:** `failed`, derived from `G3` (`1` below 10, `0` otherwise)
- **Class counts:** 100 fail and 549 pass in the source dataset
- **CSV separator in the source file:** semicolon (`;`)

The split is stratified, with 20% held out for testing and random seed 42. The
preprocessing pipeline is fitted only on the training partition. Numeric features
are median-imputed and standardized; categorical features are mode-imputed and
one-hot encoded. Class weighting is enabled for logistic regression, the decision
tree, and SVM to account for the minority fail class.

## Run locally

Use Python 3.13 to match `runtime.txt` and the saved model artifacts.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python train_models.py
streamlit run app.py
```

To train from another copy of the source file:

```bash
python train_models.py --data /path/to/student-data.csv
```

The training script writes the five fitted preprocessing/model pipelines to
`model/`, records metrics and metadata there, and exports the stratified test
partition as `test_data.csv`. The Streamlit app can evaluate that bundled file or
an uploaded labeled CSV. Uploaded CSVs must contain all 30 feature columns plus
`failed` (`0` for pass, `1` for fail). The app only loads saved models; it never
fits them on uploaded data.
